01

The Problem

Enterprise call centers for Verizon and Wells Fargo process millions of customer interactions daily. Extracting actionable intelligence — root causes of frustration, compliance violations, urgent callback intents — was a manual, inconsistent process taking hours. Critical escalations went undetected. I was tasked with building a system to automate this at production scale, with sub-5-second latency from ingest to analyst dashboard.

02

Architecture Decision

A single monolithic LLM prompt suffers accuracy degradation when handling multi-topic calls. I chose a modular parallel-agent pattern using LangGraph's StateGraph — five specialist agents running concurrently, each with a focused prompt and structured output schema enforced via Instructor + Pydantic. An Aggregator node merges their outputs into a single call record.

03

Key Tradeoffs & Decisions

Local Embeddings → Cloud API
Render's 512MB free-tier made local HuggingFace/PyTorch embeddings impossible. Switched to Google Generative AI Embeddings (text-embedding-004), eliminating heavy PyTorch dependency.
Result: âˆ’80% memory footprint. Stable cloud deployment within the 512MB constraint.
Monolith Prompt → Parallel Agents
Single-prompt approaches degrade when a call covers multiple topics simultaneously (billing + network + escalation). Parallel specialist agents maintain focus per domain.
Result: Higher per-domain accuracy. Pydantic-enforced structured outputs eliminated hallucinated JSON.
Mock Streams → Live WebSocket Broadcaster
Initial mock data wasn't production-representative and blocked real-time dashboard integration. Built a WebSocket broadcaster pushing live call updates directly to the React dashboard.
Result: End-to-end latency from ingest to analyst dashboard under 5 seconds.

How I Think

The mental models that drive every architectural decision.

on_systems_thinking()

Build for failure modes, not happy paths

Every system I design starts with: "What breaks first under load?" Production AI systems fail in ways demos never reveal — context window overflows, embedding drift, tool call timeouts, hallucinated JSON that breaks downstream parsers. I design for these edge cases before writing a single happy-path line of code.

Proof: Switched from local HuggingFace embeddings to Google Cloud API mid-project to prevent OOM crashes on constrained hosting — before they happened in production.
on_tradeoffs(decision)

Every choice is a bet. Document it.

There is no "best" architecture — only the most appropriate for your constraints. I choose LangGraph over CrewAI when I need fine-grained state control. I choose GPT-4o-mini for high-frequency low-stakes calls. I choose ChromaDB over Pinecone on constrained budgets. Every tradeoff is a documented, reasoned decision — not a gut feel.

Proof: Benchmarked 4 LLMs (GPT-4o, Claude, Gemini, Llama) across accuracy, coherence, latency, and cost — selected the optimal model per workload, achieving âˆ’35% processing time.
on_production(system)

A demo that crashes is a liability

I don't ship until I have observability. LangSmith traces for every LLM call. Pydantic schemas enforcing every agent output. 979 passing unit tests before deployment. Rate limiting to prevent cost explosions. If I can't see it, measure it, and debug it — it does not go to production.

Proof: Enforced 100 req/day rate limits on LLM API services, reducing server load by 40% and preventing uncontrolled cost bleed in a multi-tenant environment.
on_velocity(constraint)

Move fast by writing things that don't break

Real velocity comes from trust in your foundations. I write typed Python with Pydantic everywhere. I add integration tests before features. I design APIs to be backwards-compatible from day one. The payoff: when we ship fast, we don't spend the next week undoing it. POC-to-production is a pattern, not an accident.

Proof: Three consecutive POC-to-production promotions: Kinesis streaming pipeline, Salesforce–WhatsApp integration, AI call analytics system.
