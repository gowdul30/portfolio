    1. The Problem

    Enterprise call centers for Verizon and Wells Fargo process millions of calls daily, but extracting actionable insights — root causes of frustration, compliance failures, callback intents — was slow and manual. Critical escalations went unnoticed, driving churn and high operational costs. I was tasked with building a production-grade Generative AI pipeline for real-time conversational analysis.

    2. The Approach

    Instead of a monolithic LLM prompt, I architected a modular multi-agent system using LangGraph with five parallel specialist agents (Root Cause, Escalation, Sentiment, Action Items, QA). To deploy on Render's 512MB free tier, I switched from local HuggingFace embeddings to Google Generative AI Embeddings, saving 400MB+ of RAM. I designed dual storage: MongoDB Atlas for persistent records, ChromaDB for semantic vector retrieval.

    3. Execution

    Implemented the FastAPI backend with a live /api/ingest endpoint feeding transcripts into the LangGraph pipeline, mapping Pydantic output schemas to dashboard-compatible records. Built pymongo adapters for MongoDB Atlas, a vector store service with Google API embeddings, and replaced mock streaming with WebSocket broadcasting for real-time dashboard updates. Authored migration and seeding scripts for consistent startup states.

    4. The Result

    Eliminated local CPU embedding constraints, cutting memory by 80% for stable cloud deployment. Achieved enterprise-grade data durability with MongoDB Atlas, handling live real-time ingestions. The system now executes transcript extraction, agent scoring, storage, vector embedding, and dashboard updates via WebSockets in under 5 seconds.
